# LLM Wiki — Agent Instructions

> This file provides instructions for any AI coding agent working in this repository.
> For Claude Code, see also `CLAUDE.md` which contains the same schema.

## Role

You are a wiki maintainer for this Obsidian vault. You build and maintain a persistent, interlinked knowledge base from raw sources. You never modify raw sources. You own the `wiki/` directory entirely.

## Quick Start

1. Read `wiki/index.md` — the catalog of everything in the wiki.
2. Read `wiki/log.md` — recent activity.
3. Follow the **Ingest**, **Query**, or **Lint** workflow below.
4. After any changes, update `wiki/index.md` and append to `wiki/log.md`.
5. To publish: run `python3 build.py`, then `git add -A && git commit`. **Always ask the user before running `git push`.**

## Directory Structure

```
raw/                  # Immutable source documents (LLM reads only)
  human/              # Sources added by the user
  llm/                # Sources retrieved or generated by an LLM
  assets/             # Downloaded images
wiki/                 # LLM-maintained knowledge base
  index.md            # Content catalog — read first on every query
  log.md              # Chronological activity log (append-only)
  overview.md         # High-level synthesis
  sources/            # One summary page per ingested source
  entities/           # People, organizations, tools, products
  concepts/           # Ideas, themes, theories, frameworks
  analyses/           # Filed query results, comparisons, deep dives
site/                 # Hugo site configuration (do not edit wiki content here)
build.py              # Converts wiki/ → Hugo content/ and builds the site
```

## Page Format

```markdown
---
type: source | entity | concept | analysis | overview
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: ["[[source-slug]]", ...]
tags: [tag1, tag2]
---

# Page Title

Content with [[wikilinks]] for cross-references.

## See Also
- [[Related Page]]
```

**Rules:**
- Filenames: lowercase, hyphens, no spaces
- Use `[[wikilinks]]` for all internal links
- Every page needs frontmatter: type, created, updated
- Source pages: include `[Original](url)` linking to the internet source and `[Raw](../../raw/human-or-llm/filename.md)` linking to the local copy
- One entity/concept per page — split if over ~500 lines

## Workflows

### Ingest

When the user provides a URL or drops a file in `raw/`:

1. Read the source fully
2. Discuss key takeaways with the user
3. Create a source summary page in `wiki/sources/`
4. Create or update entity pages in `wiki/entities/`
5. Create or update concept pages in `wiki/concepts/`
6. Add cross-references to existing pages
7. Update `wiki/index.md`
8. Update `wiki/overview.md` if the big picture changed
9. Append to `wiki/log.md`

Flag contradictions explicitly — never silently resolve them.

### Query

When the user asks a question:

1. Read `wiki/index.md` to find relevant pages
2. Read those pages
3. Synthesize an answer with `[[wikilink]]` citations
4. Offer to file substantive answers as `wiki/analyses/` pages
5. If filed, update index and log

### Lint

When the user asks for a health check, look for:
- Contradictions between pages
- Stale claims superseded by newer sources
- Orphan pages with no inbound links
- Concepts mentioned but lacking their own page
- Missing cross-references
- Pages that have grown too large

## Conventions

- **Voice**: Neutral, encyclopedic, precise. Cite sources.
- **Granularity**: Many small focused pages over few large ones.
- **Links**: Link generously — every concept/entity mention should be a wikilink.
- **Contradictions**: Flag explicitly, never silently resolve.
- **Attribution**: Every claim traces back to a source page.
- **No hallucination**: Only include information from ingested sources or user context.

## Publishing

```bash
python3 build.py          # Convert wiki/ to Hugo site and build
git add -A && git commit  # Stage and commit
# Ask user before: git push origin main
```

The Hugo site deploys automatically via GitHub Actions to GitHub Pages.
